A custom e-commerce website I designed and built for a Zambian baking supplies store.

Overview

Cake Studio is a baking supplies store in Zambia. I built its online shop: customers browse ingredients, baking tools and packaging, choose sizes and colours, pay, and pick courier delivery or free store pickup.

The owner, Sabeta Mbola, manages orders, stock, prices and delivery fees from a simple admin dashboard. I was the only developer on the project.

The problem

The store sells many items, and most come in different sizes and colours. It needed customers to browse, choose and pay online.

Most of its traffic comes from WhatsApp, Facebook and Instagram, so the site had to work well on a phone first.

What I built

  • A mobile-first storefront for ingredients, baking tools and packaging.
  • Product variants (sizes, colours) with automatic stock tracking that prevents overselling.
  • A cart and guest checkout, so customers don't need an account.
  • Payment by MTN MoMo, Airtel Money or card, through Flutterwave.
  • Courier delivery with fees set by delivery zone, or free store pickup.
  • Order tracking and order confirmation emails.
  • WhatsApp order support.
  • An admin dashboard for orders, stock, prices and delivery fees, with low-stock alerts.

Technical decisions

The server calculates every price

The browser sends product IDs, variants and quantities. The server looks up prices and delivery fees and works out the total itself. I never take a price from the browser, so editing a request can't change what an order costs.

Stock is protected with database transactions

Checking stock and reducing it happen inside a single database transaction. If two customers try to buy the last item at the same moment, only one order can take it.

Payments are verified before an order counts as paid

An order is marked as paid when the Flutterwave webhook is verified, not when the customer lands back on the site. Webhook handling is idempotent: if the same event arrives twice, the order is processed once.

Docker setup

I packaged the app with Docker so it runs the same way in development and on the server. I used Cloudflare Tunnel to expose it to the internet.

Security

Payments and customer orders need to be handled carefully, so I treated security as part of the build.

  • Prices calculated on the server.
  • Verified and idempotent payment webhooks.
  • Rate limiting.
  • Strict security headers.
  • Hashed admin passwords.
  • Validated inputs.
  • No source maps in production.

Result

Delivered and handed over to the client. The store owner can manage orders, stock, prices and delivery fees from the admin dashboard.
